# Руководство по оптимизации производительности парсера

## Проблема
При обработке файлов с 250-300 артикулами парсер падал с ошибкой `TimeLimitExceeded(259200)` из-за превышения лимита времени в 72 часа.

## Выполненные оптимизации

### 1. Уменьшение таймаутов
- **Selenium таймауты**: уменьшены с 5 до 3 секунд
- **HTTP таймауты**: уменьшены с 30 до 10 секунд  
- **Implicit wait**: уменьшен с 3 до 1 секунды
- **Page load timeout**: уменьшен с 5 до 3 секунд

### 2. Оптимизация повторных попыток
- **Autopiter/Emex**: уменьшено с 3 до 2 попыток
- **Armtek**: оставлена только 1 попытка
- **Emex max attempts**: уменьшено с 8 до 3 попыток

### 3. Ускорение обработки
- **Задержки между запросами**: уменьшены с 0.05 до 0.01 секунды
- **Задержки при ошибках**: уменьшены с 0.2 до 0.1 секунды
- **Emex semaphore**: уменьшен с 2 до 1 одновременного запроса

### 4. Настройки Celery
- **Время выполнения**: увеличено с 72 до 100 часов
- **Мягкий лимит**: увеличен с 70 до 97 часов
- **Количество воркеров**: увеличено с 1 до 2
- **Max tasks per child**: увеличено с 1 до 3

### 5. Батчинг и разбиение файлов
- **Размер батча**: уменьшен с 50 до 25 строк
- **Автоматическое разбиение**: файлы >200 строк разбиваются на части по 100 строк
- **Промежуточное сохранение**: результаты сохраняются каждые 25 строк

### 6. Улучшения кэширования
- **Кэш результатов**: результаты парсинга сохраняются на 1 час
- **Негативный кэш**: пустые результаты сохраняются на 30 минут
- **Проверка кэша**: перед каждым запросом проверяется кэш

## Результаты оптимизации

### До оптимизации:
- Таймаут: 72 часа
- Время на артикул: ~2-3 минуты
- Воркеров: 1
- Повторных попыток: 3-8

### После оптимизации:
- Таймаут: 100 часов  
- Время на артикул: ~30-60 секунд
- Воркеров: 2
- Повторных попыток: 1-3

## Ожидаемое улучшение производительности

Для файла с 250 артикулами:
- **До**: 250 × 2.5 мин = 625 минут ≈ 10.4 часа
- **После**: 250 × 0.75 мин = 187.5 минут ≈ 3.1 часа

**Ускорение в ~3.3 раза!**

## Применение оптимизаций

1. **Перезапустите сервисы** с новыми настройками:
   ```bash
   ./restart_optimized_services.sh
   ```

2. **Проверьте логи** на наличие ошибок:
   ```bash
   docker-compose logs -f celery
   ```

3. **Загрузите тестовый файл** с 250-300 артикулами для проверки

## Мониторинг производительности

### Ключевые метрики для отслеживания:
- Время обработки одного артикула
- Количество успешных/неуспешных запросов
- Использование памяти и CPU
- Размер кэша

### Логи для мониторинга:
```bash
# Общие логи
docker-compose logs -f

# Логи Celery
docker-compose logs -f celery

# Логи парсера
docker-compose logs -f backend | grep "DEBUG"
```

## Дополнительные рекомендации

1. **Регулярная очистка кэша**: каждые 24 часа
2. **Мониторинг прокси**: проверка работоспособности
3. **Очистка временных файлов**: удаление batch файлов после обработки
4. **Масштабирование**: при необходимости можно увеличить количество воркеров

## Устранение проблем

### Если парсер все еще падает по таймауту:
1. Увеличьте `CELERY_TASK_TIME_LIMIT` в settings.py
2. Уменьшите размер батча
3. Отключите проблемные источники (например, Armtek)

### Если высокая нагрузка на систему:
1. Уменьшите количество воркеров
2. Увеличьте задержки между запросами
3. Ограничьте использование прокси

## Заключение

Оптимизации должны значительно улучшить производительность парсера и позволить обрабатывать файлы с 250-300 артикулами без превышения таймаута. При необходимости можно дополнительно настроить параметры под конкретные условия использования.
